# Contributing guidelines

For the most part, contributions are always welcome. Due to hardware availability, it's likely that some features will only ever be implemented by people who have hardware with those capabilities. However, this project is something I built and maintain in my spare time, so some rules need to exist for my own sanity.

## General guidelines

- Changes should focus on a single feature or set of related features
- Changes should not be speculative. You should be able to explain how/why your change works, and it should minimally work on your own local hardware.

## AI assistance

Use of AI tooling is fine, provided the following guidelines are followed:

- Code should be fully reviewed and understood by the submitter.
- Anything not code should be written by humans. This includes commit descriptions, PRs, code commants, etc. The person submitting the change should understand everything they're submitting, so this should not be an issue.

In general, if I can tell you've used AI, you probably did not follow these guidelines. Submitted PRs that violate these guidelines will likely be closed. Code review takes real time and nobody wants to spend their weekend writing up something to be copy/pasted into someone else's AI agent.
